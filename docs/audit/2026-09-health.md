## Sécurité

### 1. Secret d'authentification — **P1**

`src/env.ts` déclare `BETTER_AUTH_SECRET: z.string()`, donc une chaîne vide passe. Le `.env`
local est dans ce cas ; better-auth retombe alors sur son secret par défaut (sessions signées
avec une valeur publique). À vérifier sur Vercel.
**Correctif :** `z.string().min(32)` dans `env.ts` et renseigner le `.env` local
(`openssl rand -base64 32`). Non fait ici car cela casse `pnpm dev` tant que le `.env` n'est pas
rempli.

### 2. Webhook Strava — **P2** (P1 si Strava revient)

`GET` vérifie correctement `hub.verify_token`. `POST` ne vérifie rien : il fait confiance à
`owner_id` et `object_id` du corps. Un `aspect_type: "delete"` forgé supprime la course
correspondante et recalcule les records. Strava ne signe pas ses webhooks ; la parade usuelle est
de comparer `subscription_id` à l'id d'abonnement connu (variable d'env) et d'ignorer le reste.
Tant que l'app Strava est inactive, la route peut aussi être désactivée derrière le flag
`STRAVA_ENABLED` prévu en phase 2.

### 3. Tokens Strava en clair — **P2**

`StravaAccount.accessToken` / `refreshToken` stockés sans chiffrement. L'intégration étant
inactive, le plus simple est de purger ces lignes (ou de les chiffrer si Strava revient).

### 4. Actions admin — OK

Toutes les actions de `src/app/(admin)/admin/_actions/` passent par `adminActionClient`.

### 5. Routes publiques — OK / faible

`/api/og/run/[runId]` répond sans session et expose les stats d'une course. Voulu (image de
l'embed Discord) ; l'id est un cuid non devinable. La route `api/runs/[id]/gpx` citée dans
`CLAUDE.md` **n'existe plus** — documentation à corriger.

### 6. Configuration auth — OK

`trustedOrigins` limité à l'URL de l'app, rate limit 5 / 60 s, inscription coupée en production.
